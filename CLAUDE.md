# ChestnyiZnak — генераторы XML для ГИС МТ «Честный Знак»

Бесплатный клиентский веб-сервис для предпринимателей РФ: готовит XML-документы для системы
маркировки «Честный Знак» из обычного Excel/CSV. Всё считается **в браузере**, данные на сервер не уходят.
Монетизация — рекламные блоки Яндекс РСЯ.

## Стек
- **Blazor WebAssembly, .NET 9** (standalone, без сервера). Исходно в плане был .NET 8, но в системе только .NET 9 SDK.
- **Bootstrap 5** (НЕ Tailwind — Node.js не установлен, не хотим build-конвейер).
- **ClosedXML** — генерация/чтение .xlsx.
- Скачивание файлов — JSInterop (`wwwroot/js/download.js`, `downloadFileFromStream` + `DotNetStreamReference`).

## Запуск
```bash
dotnet watch run     # из корня проекта; откроется https://localhost:****
```
> При сборке параллельно с запущенным `watch` использовать `dotnet build -p:DebugType=none`
> (иначе .pdb залочен запущенным приложением).

## Аудитория / стиль
Пользователь — разработчик, знает C#, но **не знает домен маркировки**. Объяснять доменные термины
простыми словами, двигаться по шагам, не выдавать неподтверждённое за готовое.

## Архитектура
- `Pages/Home.razor` — стартовая, выбор инструмента.
- `Pages/Order.razor` (`/order`) — **Заказ кодов маркировки**.
- `Pages/Introduction.razor` (`/introduction`) — **Ввод в оборот** (5 типов).
- `Pages/Withdrawal.razor` (`/withdrawal`) — **Вывод из оборота** (`withdrawal` v8, код в `<cis>`).
- `Services/*` — вся логика (шаблоны Excel, парсеры, генераторы XML, XSD-валидация).
- `Models/*` — MarkingRow/ParseResult (ввод в оборот), OrderRow/OrderParseResult (заказ).

## Документы

### Ввод в оборот — `/introduction` (по официальным XSD, все 5 проверены валидацией)
Вход: коды КИ из **Excel-шаблона ИЛИ CSV-выгрузки из СУЗ** (`.xlsx/.csv/.txt`). Реквизиты — в форме.
Тип выбирается переключателем (`IntroductionType`):

| Тип | Корень XML | version | Поля документа |
|-----|-----------|---------|----------------|
| Производство РФ | `introduce_rf` | 9 | 3 ИНН (участник/произв./собств.) + production_order=OWN_PRODUCTION |
| Контрактное | `introduce_contract` | 7 | producer_inn + owner_inn + CONTRACT_PRODUCTION |
| Маркировка остатков | `vvod_ostatky` | 3 | только trade_participant_inn |
| Импорт с ФТС | `introduce_import_fts` | 3 | участник + номер ДТ + дата ДТ |
| Производство вне ЕАЭС | `introduce_import` | 5 | участник + дата ДТ + номер ДТ + customs_code + decision_code |

Все схемы **без namespace**; в `<product>` пишем только `<ki>` (остальное опционально).
Схема `introduce_rf` общая для большинства товарных групп (поля Молоко/Вода опциональны).

### Заказ кодов — `/order`
Корень `<order xmlns="urn:oms.order">`. Вход: GTIN(14)+количество (Excel) + параметры на странице
(contactPerson, releaseMethodType, createMethodType, serialNumberType). Фикс для легпрома:
productGroup=lp, cisType=UNIT, templateId=10. **Лимит 10 GTIN-позиций** в файле.
⚠️ Схема заказа — из форум-комментария (НЕофициальная). Поэтому генерация заблокирована,
пока пользователь не приложит официальную XSD заказа из своего ЛК → XML проверяется по ней,
скачивается только если валиден.

## Схемы и валидация
- Официальные XSD «Ввода в оборот» — публичные: docs.crpt.ru/gismt/Раздел_шаблоны_документов/
  (файлы на честныйзнак.рф/upload/docs/, домен под DDoS-Guard с геоблоком — качает пользователь из РФ).
- Скачанные схемы лежат в `temp/schemas/` (Производство_РФ, Контрактное, Маркировка_остатков,
  Импорт_с_ФТС, Производство_вне_ЕАЭС, LP_base_types).
- `Services/XsdValidationService.cs` — проверка XML по XSD в браузере. Пользователь грузит схему сам
  (она обновляется). `xs:include` базовых типов резолвится кастомным `XmlResolver`.
  ⚠️ При `dotnet publish` с тримингом проследить, чтобы не вырезался `System.Xml.Schema`.

## Домен: КИ vs КМ
- **КИ** (код идентификации) = `01`+GTIN(14)+`21`+серийник — это и нужно для «Ввода в оборот».
- **КМ** (код маркировки) = КИ + криптохвост (только внутри картинки DataMatrix).
- Коды per-единица товара. GTIN — per товарную позицию. В заказе: GTIN+количество (лимит 10 позиций).
- Вход кодов в ввод в оборот — через **CSV-выгрузку из ЛК** («Документы»→«Коды маркировки»→CSV;
  лимит 10 000 кодов/запрос). PDF-этикетки СУЗ для этого НЕ нужны (там в тексте нет криптохвоста,
  а нам и не нужен — нужен КИ).

## Бэклог
- Реальный CSV из СУЗ — прогнать через превью, при необходимости подстроить выбор столбца в `CsvCodeParserService`.
- Остальной жизненный цикл (публичные XSD есть): агрегирование/упаковки, отгрузка/приёмка,
  возврат в оборот, перемаркировка. (Вывод из оборота — сделан.)
- Коды КИ в XML (`<ki>`/`<cis>`) оборачиваются в CDATA — КИ может содержать спецсимволы
  (рекомендуемый алгоритм экранирования ГИС МТ). CSV-парсер учитывает кавычки/разделители внутри кода.
- Найти официальную XSD заказа (СУЗ) — довести «Заказ кодов» до боевого.
- Подключить рекламу РСЯ (сейчас заглушки).
- Перед прод-сборкой: проверить триминг System.Xml.Schema.
